# 搜索与复盘

从合法站位、费用到账、首个敌人经过的位置和技能就绪时机提出一条可解释的操作轴，用正式整局入口运行。保留请求、种子和结算结果，比较候选时固定关卡、编队、难度与外部条件。

试轴时可以在阵线失守处提前结束候选。关键干员意外被击倒后，查看这条轴的后续动作。如果现有费用和再部署时间已经接不上下一波所需的输出、控制或阻挡，就记下首次失守帧、受击对象和失效的下一手，回到敌人锁定或起手前改轴。玛露西尔主动撤退后在场下补魔、艾雅法拉空降开火山，以及已有接替安排的退场，均按原轴继续。提前结束的候选标为试轴剪枝。

诊断失败时找第一个改变后续局势的事件，例如部署费用不足、首个漏敌、开技时敌人已离开射程。先调整造成分歧的站位、方向或操作时机，再跑整局。对关键操作逐帧提前或延后，记录其余操作固定时实际成功的连续区间；同一轴涉及配合时再试联合变化。

需要评价随机性时，使用 `python -m tools.run_caster_seeds <请求路径> --trials <次数> --sample-seed <抽样种子>`。报告胜、负、未结算各多少局，以及地图种子是否固定。模拟器的胜利状态是 stage_victory_projected；同时检查 combat_unresolved。目标有额外条件（例如无漏敌）时还须核对剩余生命与相应事件。只给实际验证过的窗口和样本结果。

## 在关键操作处比较候选

AlphaDefect 在困难战斗中给有竞争的动作追加搜索，用同一批随机世界配对比较，再以新种子评估。这里借用其实验设计，由项目模拟器直接算结局。 [论文 §2.4、§3.1 与附录 A.2](https://arxiv.org/html/2611.31076)

1. 先保留能复跑的基准轴。只在有选择价值的节点展开，例如第一只要漏的敌人进射程时，比较立即开技、等下一只入圈、或把上一手部署换向。候选须满足当时的费用、部署位、在场状态和技能就绪条件。
2. 把候选落实为具体行动和插入帧。固定其他操作、战斗种子与地图种子，进入正式比较或交付的候选都从开局跑至结算。先按用户目标、胜负比较，再按剩余生命、操作数和实测窗口选取。若一处改动让后续操作失效，先修正并记录后续轴，再比较完整方案。
3. 有随机性时用相同 trial 数、sample-seed 和地图种子设置比较基准与候选，逐对记录哪局由负转胜、哪局由胜转负。筛选后锁定操作轴，另用未参与选择的种子对检验。只跑固定种子时标为固定种子结果。模拟器暂缺规则的样本单列为未结算。
4. 轴可使用玩家当时能看到的信号（费用到账、技力就绪、敌人经过指定格）。离线复盘可以看到后续抽签，用它定位问题；交付给玩家的分支条件必须在按键前可见。相同操作可通过时，优先选择经过扰动检查、时机更宽的方案。
