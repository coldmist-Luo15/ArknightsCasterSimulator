# 按需分析客户端安装包

用户已明确授权：必要时自行下载明日方舟安装包并调用合适解包工具，补充算轴缺失的机制和参数。无需重复请求这项授权；下载与本地分析不自动扩展为安装/启动客户端、登录或操作实机。

先列待求字段，例如 collider、攻击动画事件、弹体配置、技能资源关联、状态切换或同帧逻辑。公共数据和可靠研究不足，且包内资源可能回答时使用。

## 来源与完整性

寻找对应服务器/版本的官方公开分发包或已有本地包。记录下载页与实际 URL、版本、地区、大小、下载时间和 SHA-256，来源有校验值时核对。基础 APK、拆分包、OBB 和更新资源可能不完整；包里没有资源不等于游戏没有机制。补丁无法公开取得时保留缺口，不伪造路径或配置。

## 选择工具

先检查文件清单和格式，再定向提取；必要时查当前官方工具文档：

- ZIP/APK：已有归档工具或 Python zipfile。
- Unity AssetBundle/SerializedFile：视格式选择兼容的 UnityPy、AssetRipper、AssetStudio 等。
- Spine：按实际版本解析动画事件；画面动画帧不自动等于逻辑伤害节点。
- 托管程序集/IL2CPP：确需逻辑且包内有匹配数据时选分析工具，保留符号/偏移及版本；推断须结合调用路径和行为验证。

使用独立分析目录保留原包，解包前检查路径穿越和异常膨胀，避免覆盖项目文件。工具从可信项目发布页获取，确认用途后执行；不执行包内未知安装程序，不绕过证书或哈希检查。失败记录格式/兼容问题，不能把失败输出当有效数据。

## 进入模型

每项发现保存“原包哈希 → 内部路径/对象/字段 → 解析方法 → 值 → 语义 → 验证”。发现 collider 不等于确定所有能力都使用它；发现技能名不等于取得完整执行逻辑。确认参数和推测规则分开，为影响轴的推测设计验证。

保留本次参数和证据索引，不把大型安装包或整套素材塞进技能目录。
