# 两份操作轴

全息或合约轴在人工表和交付消息中写明实际所选词条。逐组给出互斥项所选的具体效果与分值，列出零分必选项和有数值区别的档位，用该轴请求与结果核对总分。全息 H5-1 的正式回放在 `rune_selection` 中给出包体顺序、分值和已代入数值的说明。

从同一次正式整局回放提取玩家实际执行成功的操作。用请求提供队员、位置和按键意图，再核对部署成功、技能生效、撤退或装置响应的事件；使用玩家输入的帧。自动技能、伤害落点、拒绝的按键和结算后才安排的操作不进入操作清单。若自动技能是等候信号，可写在人工表说明里。结算与未结算、失败复盘分别在标题或结果中标明。

两份交付共用一份已核对记录。记录含 `title`、`setup`（阵容、技能模组、时钟或关卡特殊设置）、`result`（实际结算、条件和已验证窗口）、`steps`（有序操作）。一行例如：

```json
{"frame":330,"operation":"部署艾雅法拉（二技能）","row":2,"col":6,"direction":"RIGHT","cost":"20 → 1","cost_bar":{"frame_in_cycle":30,"cycle_length":31}}
```

在技能目录执行 `python scripts/export_timeline.py <已核对记录.json> --out <本局交付目录>`。交付下面两份文件，附上可复跑请求和回放的位置。

- **给费用尺**的 `costbarruler.json` 使用 CostBarRuler 配套打轴器（Python 版 timeline_tool）的节点数组，每项含整数 `frame`、操作文字 `name` 和颜色 `color`。同帧操作按引擎执行顺序合为一个提醒。文件在打轴器的「打开」中加载；Rust 版尺子单独提供计时。 [打轴器读写与显示实现](https://github.com/ZeroAd-06/ArknightsCostBarRuler/tree/bd105ecfba950f740c83afc5b2121cdfa2c0b2b6/timeline_tool)
- **给人看**的 `操作轴.md` 每行写分、秒、帧（MM:SS:FF）、绝对逻辑帧、费用条读数、费用和具体操作。部署写干员、格位和朝向；开技写干员和技能，撤退或再次部署写明对象及其当前格位。PRTS.Map 格位按游戏 row 从 A 向上递增，col 从左到右加一；(0,0) 为 A1，(2,6) 为 C7。输入采用游戏坐标，读取原始格网数组时先按引擎换算。用 WD-TR-1 的安赛尔 (4,7) → E8、玫兰莎 (3,5) → D6 可复核。 [PRTS.Map 预部署位置](https://mapen.ark-nights.com/map/act18d0_tr01)
- **31 帧周期**按回放的 `cost_bar` 读取。尺子总时钟以 F0 为起点，每秒 30 帧，FF 为 00 至 29。费用周期含 N 帧时从 0/(N−1) 到 (N−1)/(N−1)。例如一秒自然回费的已核对开局中，F330 为 00:11:00、周期 30/30，F331 为 00:11:01、下一周期 0/29。其他回费速度或暂停会改变边界，费用封顶或缺采样时写实际状态或留空。只有同一帧、同一输入顺序的记录能用于填写操作前后费用。

两个文件的帧、坐标、同帧顺序都应能对回运行日志。模拟器可输出的 `logic_timecode` 可直接用来交叉检查。
